# Vouze Dev Session — May 25–26, 2026

## Supabase Changes (already live)

### New RLS Policy — profiles table
- Name: `Authenticated users can read profiles`
- Command: SELECT
- USING: `(select auth.role()) = 'authenticated'`
- Reason: previous "owner access" policy blocked reading other users' display names

### New Postgres Function
```sql
create or replace function get_display_name_by_user_id(user_uuid uuid)
returns text language sql security definer stable as $$
  select display_name from profiles where id = user_uuid;
$$;
grant execute on function get_display_name_by_user_id(uuid) to authenticated;
```
- Use this RPC any time you need another user's display name — never query `profiles` directly from the client

## Key Patterns

### Member name resolution
- `members` table stores plain name strings (display names or guest names)
- Registered users: name = their `profiles.display_name`
- Guests: name = whatever was typed
- Never store email prefixes — skip `members` insert if display name can't be resolved

### Profile lookups across users
- Always use `supabase.rpc("get_display_name_by_user_id", { user_uuid: id })`
- Never query `profiles` directly from the client — RLS blocks cross-user reads

### trip_members inserts
- Always handle 23505 duplicate errors gracefully:
```js
const { error } = await supabase.from("trip_members").insert([...]);
if (error && error.code !== '23505') throw error;
```

### Photo downloads
```js
const res = await fetch(photo.url);
const blob = await res.blob();
const a = document.createElement('a');
a.href = URL.createObjectURL(blob);
a.download = filename;
a.click();
URL.revokeObjectURL(a.href);
```

### Avatar storage format in profiles.avatar
- `photo:{url}` — uploaded photo
- `emoji:{char}` — single emoji
- `initials:{str}` — up to 5 chars
- `name:{str}` — legacy
- null — falls back to initials from display_name
